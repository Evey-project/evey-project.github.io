    Solución de problemas¶

    ¿Algo no funciona? Busca lo que ves en la tabla de abajo. La columna del medio dice dónde mirar primero; la última lleva a la solución. Si no basta, los registros y evey admin doctor (más abajo) dan más información.

    Los registros¶

    El registro (log) es el archivo donde Evey anota lo que hace: cada error se anota ahí, con la hora.

    La forma fácil: Administración → Registros y depuración. Muestra el registro con un buscador, una vista En vivo que sigue las líneas nuevas, y un filtro Zona para una sola parte (reproductor y conversión, subtítulos, detección de intros, Chromecast, inicio de sesión...). Cuando alguien te cuenta un problema, mira aquí primero, alrededor de la hora que te diga.

    Dónde están los archivos de registro
    • Los archivos están en ./evey-data/logs/, junto a tu archivo compose (/data/logs/evey-YYYY-MM-DD.log dentro del contenedor). Un archivo por día, en JSON, que se guarda 90 días por defecto (EVEY_LOG_RETENTION_DAYS).
    • docker compose logs evey muestra otra cosa: lo que el contenedor escribe mientras arranca (las líneas evey: del script de arranque, la base de datos, el banner). Léelo cuando el servidor no llega a arrancar. Una vez funcionando, el registro está en los archivos y en el panel.

    evey admin doctor¶

    Un solo comando revisa todo el servidor. Muestra una línea por comprobación, ok, WARN o FAIL, con lo que hay que hacer:

    docker exec evey-server evey admin doctor
    Qué comprueba

    La base de datos y su esquema, la clave de firma, el índice de búsqueda (y si coincide con la base de datos), las carpetas de contenido (incluido si Evey puede escribir en cada biblioteca), las carpetas de caché y de registros, ffmpeg y mkvgo, los proxies de confianza, el acceso remoto y el espacio libre en disco. --repair aplica solo las correcciones seguras (crear las carpetas que faltan y darles el propietario correcto). Termina con un código de error cuando falla una comprobación. Los demás comandos están en Línea de comandos.

    El servidor no arranca¶

    Lo que dice docker compose logs evey Qué significa
    Un mensaje de validación de la configuración Con una base de datos externa, el servidor rechaza la contraseña por defecto evey; con un Meilisearch externo, una clave vacía o de ejemplo. Corrige el valor que indica el mensaje.
    Líneas que empiezan por evey: sobre Postgres La base de datos integrada se negó a arrancar: un clúster de otra versión principal de Postgres (Actualización de versión principal de Postgres), un directorio de datos que no es un clúster de Postgres, un disco lleno, o ./evey-data/postgres en una carpeta compartida en red.
    permission denied en /cache/..., en un bucle de reinicios El volumen evey-cache pertenece a un usuario distinto del que ejecuta el servidor. Actualiza la imagen; con una imagen anterior al 2026-09-17, ejecuta una vez docker run --rm -v <project>_evey-cache:/c alpine chown -R <PUID>:<PGID> /c.

    Una contraseña de administrador perdida, una clave de firma comprometida o una base de datos dañada: Recuperación.

    Nadie puede iniciar sesión¶

    Dos causas habituales:

    • La base de datos no responde. Evey comprueba cada inicio de sesión con ella, y lo rechaza cuando no puede. El registro lo dice.
    • Falta un proxy inverso en los proxies de confianza (Administración → Acceso remoto). Entonces todos los visitantes parecen venir de la dirección del proxy, y todos comparten un mismo límite de intentos de inicio de sesión.

    El procedimiento paso a paso: Todos los inicios de sesión devuelven 401.

    Note

    Perder o sustituir la clave de firma no cierra por sí solo la sesión de nadie: las apps renuevan sus tokens. Para cerrar todas las sesiones a propósito está evey admin rotate-jwt-key, ver Recuperación.

    El servidor responde en casa pero no fuera, o las apps dicen que el acceso remoto está desactivado: Acceso remoto y HTTPS. Administración → Acceso remoto lo dice en rojo cuando el servidor es accesible desde internet mientras el acceso remoto está desactivado.

    Falla el inicio de sesión con SSO¶

    La página de inicio de sesión indica el motivo:

    • dominio no permitido: la dirección no pertenece a los dominios de correo permitidos de la tarjeta;
    • ninguna cuenta coincide: el registro está desactivado; activa Crear cuentas para nuevos usuarios SSO o crea la cuenta;
    • cuenta desactivada;
    • la cuenta existe pero no se pudo vincular: el proveedor no confirmó el correo, la vinculación está desactivada, o la cuenta está vinculada a otra identidad;
    • no disponible: no se puede llegar al proveedor; Estado y Probar la conexión en la tarjeta muestran el error.

    Una página de error que muestra el propio proveedor suele significar que la URI de redirección registrada allí no es la que muestra la tarjeta. Ver OIDC / SSO.

    Los correos no llegan¶

    Enviar correo de prueba en Administración → Configuración del servidor → Correo / SMTP envía un mensaje a tu propia dirección con los ajustes guardados, y muestra la respuesta del servidor de correo cuando falla. El error habitual es un modo TLS que no corresponde al puerto (starttls con 587, ssl con 465). Un host guardado en la tarjeta sustituye a todas las variables EVEY_SMTP_*. Los envíos de notificaciones que fallan se anotan como email: send notification. Ver Notificaciones.

    Problemas de reproducción¶

    Empieza por Información del flujo en el reproductor. Dice cómo se envía la película (tal cual, copiada en otro formato o convertida), pista por pista, y por qué. Si un título se convierte cuando esperabas que se reprodujera tal cual: ver Cómo se decide la reproducción.

    • Un título se detiene, no para de cargar, o tarda en saltar a otro momento: abre Administración → Salud de medios. Las causas habituales son un archivo sin índice de posicionamiento para saltar, un tramo dañado, o pistas guardadas en bloques grandes. La mayoría se pueden reparar. Ver Salud de los medios.
    • Varios títulos, cuando ven varias personas: puede que el servidor esté al límite de lo que puede convertir. Administración → Estado del sistema muestra lo ocupado que está. Ver Transcodificación y capacidad del servidor.
    • La reproducción transcodificada falla directamente: La transcodificación falla.
    • Se queda cargando y los registros no dicen por qué: el procedimiento de diagnóstico.
    • No hay sonido solo en un navegador, con una pista Dolby Digital (AC-3/E-AC-3): un proxy inverso que pone su propia Content-Security-Policy puede bloquear el decodificador que usa el reproductor web. Ver Audio.
    • El sonido va desfasado en un título: Administración → Salud de medios detecta el audio que empieza después de la imagen y las pistas que no coinciden entre sí.
    • Los subtítulos no aparecen: Subtítulos dice qué formatos dibujan los reproductores y cuáles tiene que incrustar el servidor en la imagen.
    • Preparando subtítulos… se queda varios minutos: el archivo no tiene índice para esa pista y el servidor lo lee entero, una vez. Ver La primera vez que se muestra un subtítulo.
    • Los títulos transcodificados no arrancan o se detienen mientras los títulos ya reproducidos siguen funcionando, o los administradores reciben Caché de subtítulos llena: el disco está por debajo de su margen de espacio libre. Ver La caché de transcodificación.

    Biblioteca y pósteres¶

    Los pósteres y las imágenes de fondo se copian al servidor durante los escaneos, en ./evey-data/artworks, y los que faltan se vuelven a intentar cada hora. Administración → Caché de artworks muestra cuántos siguen sin copia local; Descargar artworks faltantes los descarga ahora, y Purgar variantes corruptas quita los pósteres redimensionados que un redimensionado fallido dejó vacíos, que se vuelven a generar cuando hacen falta.

    Un póster o un título que pertenece a otra película es un problema de coincidencia de metadatos, no de imágenes: Corregir un título equivocado o que falta.

    Un archivo nuevo aparece normalmente en unos minutos (ver Cómo se detectan los archivos nuevos). Si no aparece, pulsa Escanear en la fila de la biblioteca en Administración → Bibliotecas y lee el resultado.

    Un escaneo termina con Escaneo parcial: no se pudieron leer estas carpetas: seguido de rutas: Evey no puede leer esas carpetas (permisos, una carpeta compartida en red que se ha desconectado). El resto de la biblioteca se escanea, y los títulos de una carpeta ilegible se conservan en lugar de borrarse. Revisa el montaje y el propietario (PUID/PGID, ver Instalación), y vuelve a escanear.

    La búsqueda no devuelve nada: reconstruye el índice de búsqueda a partir de la base de datos con docker exec evey-server evey admin reindex-search. No se pierde nada: el índice siempre se puede reconstruir.

    Informar de un problema¶

    Escribe a contact@eveyproject.org. Un informe útil dice:

    • qué hiciste, qué esperabas y qué pasó en su lugar;
    • cuándo pasó, al minuto: los registros se buscan por hora;
    • el dispositivo y la app: Ajustes → Acerca de → Versión de la app en la app de Android, el navegador y su versión para la app web;
    • la versión del servidor: docker exec evey-server evey version;
    • para un problema de reproducción, el título y una captura de pantalla de Información del flujo (ver Leer la información del flujo): indica el método elegido y sus motivos, que es la mayor parte del diagnóstico.

    Un administrador puede añadir las líneas del registro de ese momento (Administración → Registros y depuración, ver Los registros) y el informe de evey admin doctor. Los registros contienen nombres de cuentas y direcciones de red: léelos antes de enviarlos.

    Un fallo de seguridad no se cuenta en un sitio público: escribe a security@eveyproject.org, y deja tiempo para que se corrija antes de hablar de él.
